## What was checked, and how

Read: `index.html`, `assets/app.js`, `assets/app.css`, `assets/workbench.js`,
`assets/companion.js`, `release.sh`, `tools/check-routes.mjs`, `TODO.md`,
`README.md`, `docs/AUTHORING.md`. Ran `HH_OFFLINE=1 ./release.sh --check`:
everything that ran, passed.

Measured with a headless Chromium driven over CDP, at 390x844 (mobile), 950
and 1280 wide, on `#/track`, `#/unit/switch`, `#/unit/nand`, `#/work/switch/1`
and `#/paths`. Every layout claim above is a computed style or a bounding
box from that run, not a reading of the CSS.

What was fine: the header nav fits on one line down to 900px, the page never
scrolls sideways at 390px, the tab bar and its safe-area padding work, touch
targets on the routes that do render are at their stated sizes, the release
gates all hold, and no user-supplied string reaches `innerHTML` unescaped.

## What is not in this pass

- A layout regression test. The repo's release check runs without a browser
  and should keep doing so; the layout claims here were verified by hand and
  the fix that makes them hold is a CSS gate, not a screenshot diff
- `og:image` is a relative URL, which social previews ignore. It needs the
  deployed origin, which the repo does not know
- A content security policy. The runner address is whatever the reader typed,
  so `connect-src` would have to be `https:`, which is not a policy
